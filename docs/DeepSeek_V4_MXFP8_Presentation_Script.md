## 0:00–0:45｜开场与总体结论

**指图：** 整体页面，先指左侧三条线，再横向扫过顶部六个阶段。

**讲述：**

这一页是 DeepSeek V4 MXFP8 的整体实施路线，主要回答三个问题：第一，需要建设哪几条工作线；第二，三条线之间在哪些节点存在依赖；第三，项目怎样从基础能力推进到工程可用和实际上线。

整个方案可以先概括为一句话：MindSpore 算子、MindSpeed Runtime 和 DeepSeek V4 网络适配三条工作线并行推进；实际可运行能力按照“算子 → Runtime → 网络”逐层交付；项目级汇聚和验收以网络结果为主轴。

**强调：** 三线并行、逐层交付、网络主轴。

## 0:45–2:15｜三条工作线及职责边界

**指图：** 页面左侧绿色、蓝色、橙色三条工作线。

**讲述：**

先看三条工作线各自负责什么。

最上面绿色的是 MindSpore MXFP8 算子线，负责真实的底层计算能力，包括数据和 scale 表示、量化、Dense MatMul、MoE Grouped MatMul，以及后续融合算子。

中间蓝色的是 MindSpeed MXFP8 Runtime 线。它基于 MindSpore 算子，提供接口契约、Context、Recipe、Tensor 表示、算子调度，以及分布式、日志、缓存和生命周期等工程支撑。Runtime 定义上下文启停的通用语义，但不决定哪个网络模块开启低精。

最下面橙色的是 DeepSeek V4 网络线。网络侧建立 BF16 基线，提出候选范围，再根据 Runtime 契约和算子能力确定实际覆盖范围。Dense、MoE 由网络通过配置和上下文放置分别控制，精度、稳定性、性能和上线验收也在网络侧完成。

所以三条线的边界是：算子解决“能不能算”，Runtime 解决“怎样通用地运行”，网络解决“在哪里开启，以及结果是否达标”。

**强调：** 真实计算、通用运行、网络决策与验收。

## 2:15–3:05｜阶段一：基础能力准备

**指图：** 阶段一整列，以及页面底部左侧“阶段规则”。

**讲述：**

阶段一三条线同时启动。算子侧确定 dtype、scale、输入输出、Shape、精度和异常语义，并形成基础表示、量化和 Dense 计算能力。Runtime 同期制定接口契约和基础框架，在算子就绪后完成 Dense Runtime 验证。

网络侧独立建立 BF16 精度和性能基线、梳理候选范围；Runtime 契约和算子边界明确后，再冻结首版实际覆盖范围和 Dense、MoE 配置。

这里需要特别强调退出条件：网络线在阶段一正常推进，但不作为阶段一的项目退出条件。阶段一结束只检查基础算子和 Dense Runtime 是否已经达到网络接入条件。

**强调：** 协同定契约、网络并行准备、首阶段退出条件。

## 3:05–4:25｜Dense 与 MoE 两个交付门

**指图：** 阶段二、阶段三的两组竖向箭头。

**讲述：**

阶段二和阶段三是两个结构相同的交付门，箭头表达的就是逐层依赖。

Dense 路径先由 MindSpore 提供基础表示、量化和 Dense MatMul；Runtime 再打通正向、反向和完整训练 step；最后网络完成接入、配置启停，以及相对 BF16 的精度、显存和性能比较。网络结果完成汇聚，Dense 阶段才算项目级完成。

MoE 路径同样是先算子、再 Runtime、最后网络：算子提供 Grouped MatMul 和分组量化，Runtime 完成 Expert 调度和组合运行，网络覆盖主要 TP、EP 组合并完成汇聚。

排期上，这两个阶段不能完全串行。Dense 联调期间，算子线要提前推进 MoE 算子，Runtime 也要基于算子进度提前推进 MoE Runtime，为下一交付门预留联调和问题修正时间。

**强调：** 算子先行、Runtime 承接、网络汇聚、MoE 提前推进。

## 4:25–6:30｜工程可用：验证与性能增强闭环

**指图：** 阶段四整列，重点指橙色“工程可用”卡片和其中的增强顺序。

**讲述：**

Dense 和 MoE 功能路径打通之后，阶段四的目标不是简单地说明“MXFP8 可以运行”，而是形成工程可用能力。

第一步是扩展到目标多机规模，完成中长周期精度、稳定性、显存和资源效率验证，并利用日志和覆盖识别能力定位端到端瓶颈。普通 TP、EP 和工程支撑融入 Runtime 与网络的本阶段工作。

第二步是根据端到端数据按优先级推进性能增强。第一优先级是通算融合，例如 All-Gather 与 MatMul、MatMul 与 Reduce-Scatter 的融合。它同时涉及底层融合算子和 Runtime 调度，所以由 MindSpore 算子线与 MindSpeed Runtime 线联合交付。

第二优先级是梯度累加融合，同样同时涉及算子和 Runtime，也由两条线联合推进。

第三优先级是缓存复用及其余优化，主要由 Runtime 负责。网络侧提供端到端数据、确认瓶颈，并在每项增强后重新验证性能和精度。

因此这一阶段形成的是一个闭环：先做端到端验证和瓶颈定位，再依次评估通算融合、梯度累加融合、缓存复用及其余优化，之后回到网络侧复验。达到工程指标后收口，而不是由某一条线单独宣布完成。

工程可用的最终标准包括四点：目标规模下训练稳定；精度满足基于 BF16 基线冻结的标准；端到端性能收益明确并且可重复；关闭相应低精配置后能够执行原有 BF16 路径。

**强调：** 先验证后增强、联合交付、网络复验、端到端指标。

## 6:30–7:20｜逐步上线与持续优化

**指图：** 阶段五“逐步上线”和阶段六“持续优化”。

**讲述：**

工程指标满足以后进入逐步上线。首先在验证任务中开启 MXFP8，确认配置和实际低精覆盖一致；验证通过后，再扩大到更多任务和更大训练规模。上线过程中持续观察精度、稳定性和性能指标，出现异常时关闭对应的 Dense、MoE 或全部低精配置，执行原有 BF16 路径。

首版稳定使用以后，三条线继续并行优化：算子侧扩大融合覆盖并补充新的低精算子；Runtime 进一步优化缓存复用并接入新增能力；网络侧扩大低精覆盖范围，并验证更多网络和训练场景的收益。

**强调：** 验证任务起步、逐步扩大、配置关闭、持续优化。

## 7:20–8:00｜排期结论与收口

**指图：** 页面底部右侧“项目主轴”，再回看三条工作线。

**讲述：**

最后回到排期方法。三条工作线需要分别拆分任务和统计单线完成度，但项目整体不按某一条线的完成比例判断，而是以 Dense 网络汇聚、MoE 网络汇聚、工程可用和逐步上线四个网络节点衡量。

因此排期需要保证：对应算子能力早于 Runtime 验证窗口就绪，Runtime 能力早于网络联调窗口就绪；三条线并行推进，在网络节点完成汇聚。这样既保留各条线独立排期，也能够把跨线依赖和项目关键路径体现出来。

**强调：** 分线排期、提前交付、网络节点衡量项目进度。

## 讲演提醒

- 正常技术汇报语速即可，开场和结尾略慢，避免为了覆盖任务卡而加速。
- 不逐项朗读所有卡片，重点讲三条线的边界、Dense/MoE 箭头和阶段四闭环。
- 讲到阶段四时适当停顿，依次指出三项性能增强及责任归属。
- “配置关闭”指关闭对应低精范围并执行原有 BF16 路径，避免使用“模型回退”表述。
- 结尾必须回到排期逻辑：算子早于 Runtime、Runtime 早于网络，项目以网络汇聚点衡量。
