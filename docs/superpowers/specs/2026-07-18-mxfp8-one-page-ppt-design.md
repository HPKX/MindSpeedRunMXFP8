# DeepSeek V4 MXFP8 单页 PPT 设计说明

## 1. 设计目标

用一页 16:9 PPT 表达 DeepSeek V4 MXFP8 的整体实施路线，重点回答三个问题：

1. 三条工作线分别承担什么工作。
2. 算子、Runtime、网络之间在哪些节点发生依赖。
3. 项目如何从基础能力准备推进到工程可用和逐步上线。

页面服务于整体排期讨论，不展开具体接口、算子实现或网络代码细节。

## 2. 核心结论

- MindSpore 算子、MindSpeed Runtime、DeepSeek V4 网络适配三线并行推进。
- 接口契约和算子规格在第一阶段协同确定。
- 实际可运行能力按“MindSpore 算子 → MindSpeed Runtime → DeepSeek V4 网络”逐层交付。
- 第一阶段退出只检查基础算子和 Dense Runtime 是否达到网络接入条件，不对网络线设置退出要求。
- Dense、MoE、工程可用和逐步上线是项目级汇聚点，均以网络结果为主轴。
- 工程可用阶段先做端到端验证，再按优先级推进性能增强并复验。

## 3. 页面信息架构

页面采用“3 条工作线 × 6 个阶段”的横向矩阵。

### 3.1 三条工作线

从上到下排列：

1. MindSpore MXFP8 算子：提供真实计算能力。
2. MindSpeed MXFP8 Runtime：完成封装、调度和工程支撑。
3. DeepSeek V4 网络适配：承接项目汇聚和最终验收。

网络线使用更强的视觉强调，体现项目主轴，但三条线均保留完整任务和并行进度。

### 3.2 六个阶段

从左到右排列：

1. 基础能力准备。
2. Dense 网络汇聚。
3. MoE 网络汇聚。
4. 工程可用。
5. 逐步上线。
6. 持续优化。

Dense、MoE、工程可用三个阶段标题标记为“交付门”。

## 4. 三条工作线内容

| 工作线 | 阶段 1 | 阶段 2 | 阶段 3 | 阶段 4 | 阶段 5 | 阶段 6 |
| --- | --- | --- | --- | --- | --- | --- |
| MindSpore 算子 | 规格、基础表示、量化、Dense MatMul | Dense 联调；提前推进 MoE 算子 | Grouped MatMul、分组量化、MoE 正反向 | 通算融合；梯度累加融合 | 上线阻塞问题修复 | 扩大融合覆盖；新增低精算子 |
| MindSpeed Runtime | 契约、Context、Recipe、Tensor、Dense Runtime | Dense 联调；提前推进 MoE Runtime | Expert/Grouped MatMul 调度；Dense+MoE 组合运行 | TP/EP、日志定位；参与两类融合；缓存复用及其余优化 | 上线阻塞问题修复 | 进一步缓存复用；接入新增算子能力 |
| DeepSeek V4 网络 | BF16 基线、候选/实际覆盖范围、Dense/MoE 配置 | Dense 正反向、完整 step、启停和短周期比较 | MoE 接入、Dense+MoE 组合、主要 TP/EP 组合 | 规模、精度、稳定性、性能验证与复验 | 从验证任务扩大到更多任务和训练规模 | 扩大低精覆盖范围；接入更多网络 |

## 5. 依赖表达

依赖直接嵌入三条工作线，不设置独立的交付链条区域。

### 5.1 第一阶段

- Runtime 契约与算子规格协同确定。
- 算子基础能力完成后，Runtime 基于对应算子验证 Dense 可运行能力。
- 网络线同期推进 BF16 基线、低精覆盖范围和配置准备。
- 页脚明确：网络线进度不作为第一阶段退出条件。

### 5.2 Dense 交付门

在阶段 2 使用短竖向箭头表达：

```text
基础算子就绪
    ↓
Dense Runtime 就绪
    ↓
Dense 网络汇聚
```

算子和 Runtime 卡片同时提示正在提前推进下一阶段的 MoE 能力。

### 5.3 MoE 交付门

在阶段 3 使用短竖向箭头表达：

```text
MoE 算子就绪
    ↓
MoE Runtime 就绪
    ↓
MoE 网络汇聚
```

### 5.4 工程可用交付门

工程可用卡片内部展示验证和增强闭环：

```text
端到端验证
  → 1. 通算融合
  → 2. 梯度累加融合
  → 3. 缓存复用及其余优化
  → 端到端复验
  → 工程可用
```

性能增强按优先级推进，每项完成后回到网络侧复验，端到端指标达到工程标准后收口。

## 6. 性能增强责任归属

| 优先级 | 性能增强 | 责任工作线 |
| --- | --- | --- |
| 1 | 通算融合 | MindSpore 算子 + MindSpeed Runtime |
| 2 | 梯度累加融合 | MindSpore 算子 + MindSpeed Runtime |
| 3 | 缓存复用及其余优化 | MindSpeed Runtime |

页面中使用小型文本标签表达责任归属：

- 算子阶段 4 卡片使用“算子 + Runtime”标签，承载通算融合和梯度累加融合。
- Runtime 阶段 4 卡片使用“Runtime”标签，同时说明参与前两项联合交付，并承载缓存复用及其余优化。
- 联合责任标签采用中性色，不使用双色分割卡片。

## 7. 视觉设计

### 7.1 整体布局

- 画幅：16:9。
- 顶部：深蓝标题区，包含主标题和一句路线说明。
- 中部：三条工作线与六个阶段构成主矩阵。
- 底部：仅保留阶段规则和项目主轴，不重复绘制依赖链条。

### 7.2 色彩

- MindSpore 算子线：绿色。
- MindSpeed Runtime 线：蓝色。
- DeepSeek V4 网络线：橙色，并使用更强边框和阶段强调。
- 阶段标题：深灰到橙色的阶段序列。
- 背景：浅灰白，减少大面积高饱和色。

### 7.3 信息密度

- 每个任务卡只保留任务名称和 2 至 3 行关键词。
- 页面不使用 A0、A1、B0、C0 等内部编号。
- 依赖箭头只出现在 Dense、MoE 交付门，避免跨页面长连线。
- 性能增强顺序放在工程可用卡片内部，不额外增加图例或工作线。

## 8. 页脚内容

阶段规则：

> 阶段 1 退出：基础算子与 Dense Runtime 达到网络接入条件；网络线不作为退出条件。

项目主轴：

> Dense 汇聚 → MoE 汇聚 → 端到端验证 / 性能增强 → 工程可用 → 逐步上线。

## 9. 设计验收标准

- 一眼能够识别三条工作线和六个阶段。
- 能够沿竖向箭头读出算子到 Runtime、再到网络的 Dense/MoE 依赖。
- 能够识别网络线是项目汇聚主轴，同时看到另外两条线并行推进。
- 能够读出工程可用前的性能增强优先级和责任归属。
- 第一阶段退出条件、网络 BF16 基线、低精覆盖范围、配置启停均在页面中体现。
- 100% 页面缩放下主要文字可读，卡片之间无重叠和截断。
